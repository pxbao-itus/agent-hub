## What Agent Hub is for

Agent Hub keeps reusable building blocks for people and AI agents in one
versioned, searchable place. Instead of copying instructions between chats or
projects, your team can maintain one source and let authorized users or agents
retrieve the current version.

The main artifact types are:

- **Prompt** — reusable text that can contain variables.
- **Skill** — instructions plus optional supporting files for an agent.
- **Kit** — a collection of related prompts, skills, or nested kits.
- **Doc** — reference material that can inform plans and projects.
- **Plan** — an overview and a list of trackable tasks.

Projects organize docs and plans around an initiative. Workflows organize work
into stages and can attach the artifacts needed at each stage.

## Understand spaces and visibility

Every artifact belongs either to your personal space or to an organization,
department, or team space. The owner space determines who may manage it.
Visibility controls who may discover it.

- Use a personal space for drafts or material that belongs to you.
- Use a group space when a team should maintain the artifact together.
- Use sharing for a specific person who is outside the normal group access.

Creating an artifact in a group does not automatically give unrelated users
access. Assignment also does not grant access by itself.

## Complete your first workflow

1. Search for an existing artifact before creating a duplicate.
2. Choose the artifact type that matches the intended use.
3. Select the correct owner space and visibility.
4. Add a clear title, short description, useful tags, and the reusable content.
5. Save the artifact and review its detail page.
6. Add it to a project, kit, or workflow when it belongs to a broader effort.
7. If an AI agent needs it, create a scoped MCP token and connect the client.

Each later save creates a new immutable version. You can inspect or compare
older versions and roll back without deleting history.

## Good starting habits

- Prefer a focused artifact over one large document covering unrelated tasks.
- Use stable tags that describe domain or purpose.
- Put shared material in the narrowest appropriate group space.
- Give tokens and users only the access they need.
- Treat Docs as reference, Plans as executable work, and Projects as the
  container that connects them.
