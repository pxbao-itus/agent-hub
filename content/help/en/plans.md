## When to use a Plan

A Plan connects an overview with an ordered list of tasks. Use it to turn a
goal, Doc, or project outcome into work that people and agents can update.

Task status follows a simple flow:

- **Todo** — not started.
- **Doing** — actively in progress.
- **Done** — completed.

## Create a useful Plan

1. Choose the owner space and visibility.
2. Explain the goal, scope, and important constraints in the overview.
3. Break the work into tasks with observable outcomes.
4. Order tasks by dependency or recommended execution sequence.
5. Link supporting Docs and add the Plan to the relevant Project.
6. Assign responsibility only after the selected users have access.

Keep tasks small enough to change status meaningfully. Put detailed reference
material in a Doc and link it rather than overloading each task.

## Track progress

Update task status as work advances. Plan progress is derived from the task
states and can also be updated by an authorized AI agent through MCP.

Plan assignment applies to the artifact as a whole, not to individual tasks.
The assigner communicates who delegated the work; assignees communicate who is
responsible. Assignment does not grant access.

Edits to the Plan body create immutable versions. Task status is operational
state and should not be confused with body version history.
