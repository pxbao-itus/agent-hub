## What a Workflow tracks

A Workflow represents a repeatable sequence of stages. Each stage has a status,
optional execution notes and acceptance criteria, one responsible user, a due
date, and references to the artifacts needed for that part of the work.

Use a Workflow when progress depends on moving through a process, not only on
completing an unordered collection of tasks.

## Create and operate a Workflow

1. Choose the owner group and optionally link a Project.
2. Define stages with names that describe outcomes or checkpoints.
3. Order stages in the expected execution sequence.
4. Add concise Markdown context and acceptance criteria where a handoff needs
   more than the stage name.
5. Optionally assign one responsible user and due date. Assignment does not
   grant access; only users who can already view the Workflow are eligible.
6. Attach Prompts, Skills, Docs, or Plans where they are needed.
7. Move a stage through todo, doing, and done as work advances. Managers and
   the responsible user can report status.
8. Review overall progress and recent activity.

Artifacts remain independently owned and versioned. Attaching one to a stage
does not copy it and does not bypass its access rules.

## Keep the process useful

- Use stages for meaningful transitions, not every small task.
- Put detailed execution steps in a Plan or Skill.
- Put reference material in Docs.
- Review attachments when a process changes so agents do not retrieve obsolete
  guidance.

When a Workflow is linked to a Project, its progress is visible from the Project
context. Project membership and artifact access still remain separate.
Assigned, accessible stages also appear in **My Work**. Write-enabled MCP
clients receive the same stage context and follow the same status permissions.
