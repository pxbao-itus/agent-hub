## What a Project organizes

A Project groups Docs and Plans around one initiative. It provides a shared
place to see the reference material, planned work, members, and related
Workflows without changing the ownership of each artifact.

Use a Project for a product change, investigation, migration, or other effort
with a clear boundary. Do not use it as a replacement for organization and team
spaces.

## Set up a Project

1. Choose the group that owns the Project.
2. Give it a clear name and outcome-focused description.
3. Add the Docs that explain requirements, decisions, or findings.
4. Add the Plans that track implementation work.
5. Add members who need to discover and participate in the Project.
6. Link a Workflow when the effort follows defined stages.

A Project reference does not move an artifact into the Project owner space.
Each Doc or Plan keeps its own visibility, owner, assignment, and version
history.

## Access and membership

A person added as a Project member must still satisfy the access rules for each
artifact. If someone sees the Project but not one of its items, review the
artifact owner space, visibility, and shares.

Project managers can add or remove artifacts and members according to their
group permission. Use the narrowest group that represents the people
responsible for maintaining the Project.
